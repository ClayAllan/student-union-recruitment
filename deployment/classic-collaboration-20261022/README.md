## 2026-10-22进度

独立后端已在Ubuntu本机8790启动，生产总负责人已创建。待执行现有HTTPS站点入口切换，并进行公网登录和业务验收。GitHub Pages仍使用旧展示基线，待云端切换成功后更新入口；源码上传不表示公网切换已完成。

本次部署采用新空白库，旧服务、程序和数据库保留。新版不读取旧权限增强版数据库，不继承旧账号、会话或认证器。本目录不包含任何运行数据库、运行密码或密钥。

## 通过文件上传切换入口

服务器无法下载GitHub时，用已有可信终端连接的文件上传功能，将`switch_https.py`上传到`/home/ubuntu/`，然后在Ubuntu终端执行：

```bash
printf '%s\n' '1215746077d15567f52b4e746a0d05fc93aba2b738fabc6198f1d6ea5be50a12  /home/ubuntu/switch_https.py' | sha256sum -c - &&
sudo python3 -B /home/ubuntu/switch_https.py
```

脚本针对已核对的`/etc/nginx/sites-available/recruitment-ip`，要求恰好一处`proxy_pass http://127.0.0.1:8787;`，改为8790；配置不一致或已切换时停止。保留现有TLS、ACME和代理头，不另建重复站点，也不开放8790公网端口。

先对两份旧库和新库进行SQLite一致性备份，保存旧Nginx、旧service及覆盖配置、旧加密密钥到`/var/backups/recruitment/classic-cutover-<UTC时间>/`。目录权限0700，密钥副本0600；不要把备份、密钥内容或数据库发到聊天或公开仓库。

切换后通过回环连接检查实际HTTPS站点，使用公网IP作为证书身份、SNI和Host，不关闭TLS证书验证。失败且无新增应用审计活动、配置未被外部修改时恢复原配置；如已有新登录或业务操作，则拒绝自动退回旧数据库入口，保留现场并报告。脚本不恢复、覆盖或删除任何数据库。

正常输出`SWITCH_OK`、新版健康JSON，以及新备份和定时器检查通过后的`NEW_DATABASE_BACKUP_OK`。出现`STOP`时回传非敏感输出，不要重新安装或盲目还原旧库。切换完成后应另行核对公网访问、生产登录、部门与任务权限、保存和退出。

## 检查范围

切换助手通过9项本地虚构/模拟检查：成功保留、配置失败恢复、HTTPS失败恢复、有新活动拒绝倒流、无管理员拒绝、未知路由拒绝、备份失败不倒回健康入口、重复执行拒绝和错误健康身份拒绝。未把模拟结果等同于目标机执行或公网业务验收。

若网络下载可用，curl应设置连接和总超时；下载后核对SHA256，不关闭证书验证或使用不明镜像传递代码。实际服务器环境变化后应重新核对配置，不能把针对当前IP站点的脚本当作通用安装器。
