# 使用指南

本指南面向学生会总负责人及部门负责人，介绍报名、面试和录取的日常操作。服务器安装、账号创建和HTTPS配置请参阅[部署说明](../20261017_协作版部署与验收说明.md)。

## 一、开始之前

系统有两种运行方式：

| 方式 | 数据保存位置 | 适用场景 |
| --- | --- | --- |
| 静态演示 | 当前浏览器 | 使用虚构数据体验功能 |
| 负责人协作版 | 服务器共享数据库 | 总负责人和各部门共同开展招新 |

静态演示中的角色切换用于体验不同视角；协作版按实际登录账号限制权限。

协作版账号由管理员创建，没有公开注册入口，也不提供学生在线报名。报名信息由总负责人通过文件导入。

首次使用共享数据库时，数据为空。原浏览器中的数据不会自动迁移，需要总负责人明确导入。

## 二、总负责人操作

### 1. 设置本轮规则

进入“招新规则”，检查：

- 各部门录取名额；
- 报名截止和面试结束时间；
- 调剂等可配置规则；
- 通知文案模板。

确认后点击“保存规则”。重要规则建议在招新开始前确定。

### 2. 导入报名信息

1. 进入“报名数据”。
2. 首次使用时，可先下载Excel模板，了解字段格式。
3. 整理报名表，检查学号、姓名、学院和志愿信息。
4. 点击“导入表格”，选择文件。
5. 根据系统提示核对导入情况。

标准模板的“可面试时间”填写学生空闲区间，例如：

```text
2026-10-20 18:30–20:00；2026-10-21 19:00–21:00
```

现有报名表中的“一志愿面试时间”等字段表示已经安排的面试，不等同于学生空闲区间。

导入后，抽查学生信息、志愿顺序、空闲时间和已有排期是否正确。

### 3. 检查各部门进度

通过工作总览、报名数据及面试记录查看进度。

总负责人主要负责汇总和审核；本部门时段、排期、评价及候选排序由部门负责人维护。

### 4. 生成与审核录取建议

1. 确认部门已完成必要的面试评价和候选排序。
2. 检查各部门名额及调剂设置。
3. 进入“三志愿匹配”，生成录取建议。
4. 核对“录取结果”，检查人数、部门和志愿情况。
5. 审核后导出录取结果Excel。

候选排序、名额或评价结论发生变化后，应重新生成并审核录取建议。

### 5. 生成通知文案

通过面试排期或录取结果中的批量短信入口生成文案，核对姓名、时间、地点和部门。

系统目前只生成文案和发送清单，不会直接发送短信。

## 三、部门负责人操作

### 1. 查看本部门报名者

登录本部门账号，进入“报名数据”，可按姓名、学号及报名状态筛选。

“未排期”只检查本部门：即使学生已安排其他部门的面试，只要尚未安排本部门面试，仍会出现在本部门的“未排期”结果中。

### 2. 设置面试时间

进入“面试排期”，配置：

- 单面或群面；
- 对应面试时长；
- 群面每批最多人数；
- 场次间隔；
- 本部门可安排的日期、开始和结束时间。

完成后点击“保存本部门设置”。

部门可安排时段是可使用的时间范围，系统会按面试时长和场次间隔切分场次。

### 3. 安排面试

使用自动排期时，先查看预览，再应用结果。

重点检查：

- 是否有跨部门面试冲突；
- 是否超出学生提供的空闲时间；
- 是否有学生因容量不足而未被安排；
- 面试日期、时间和地点是否正确。

容量不足时，应调整部门时段或安排方式，再处理未安排学生。系统不会自动将面试延长到部门时段之外。

### 4. 填写面试评价

进入“面试记录”，找到对应场次和学生，填写评价、结论及必要说明。

已经填写的评价可以编辑。保存时应核对学生及部门，避免记录错位。

### 5. 调整候选排序

进入“部门排序”，按本部门讨论结果调整顺序。

支持上下移动及指定名次交换。指定名次交换会交换两人的位置，不会将中间所有人依次顺移。

排序完成后，通知总负责人重新生成录取建议。

## 四、多人协作与保存

协作版顶部会显示同步状态。

- “正在保存…”：等待保存完成。
- “已同步”：当前修改已保存到服务器。
- “已同步其他负责人的更新”：页面已获取其他账号的更新。
- 保存失败或冲突提示：修改尚未确认保存成功，应先处理提示。

系统通常约每6秒检查一次更新。正在编辑、打开弹窗或存在未同步修改时，可能暂缓获取更新。

关闭页面或退出登录前，应确认显示“已同步”。

### 保存冲突怎么办

1. 保持当前页面打开。
2. 点击“导出未同步草稿”，保存尚未同步的内容。
3. 点击“刷新服务器数据”，仔细阅读确认提示。
4. 根据最新数据和草稿重新进行必要修改。
5. 确认最终显示“已同步”。

刷新服务器数据会放弃当前页面未同步修改，必须先保存草稿。草稿用于保留和核对修改，不会自动合并到服务器。

## 五、数据保管

真实报名表、联系方式、录取名单、数据库备份及未同步草稿属于内部材料，不应上传到公开GitHub仓库或公开截图。

仓库中的示例、操作演示和问题反馈应使用虚构数据。
